# Kanleaf v0.1 Rewrite Implementation Plan

This plan implements the approved design in vertical, testable capabilities.
Each numbered section ends in a coherent local commit after its verification
commands pass.

## 1. Repository and desktop foundation

- Add the root Cargo and pnpm workspaces, repository-specific ignore rules,
  editor settings, license, and task scripts.
- Manually scaffold a browser-renderable React, TypeScript, and Vite package in
  `apps/desktop` with a minimal Tauri v2 shell in `src-tauri`.
- Configure strict TypeScript, ESLint, Prettier, Vitest, and the Tauri capability
  required by the shell.
- Replace all generated demo UI with a minimal Kanleaf boot screen.
- Verify Cargo metadata, TypeScript checking, unit tests, and a production web
  build.

Commit: `chore(repo): initialize Kanleaf workspace`

## 2. Server and PostgreSQL foundation

- Add `apps/server` as one Axum crate with validated environment configuration,
  shared application state, tracing, CORS, shutdown handling, and `/api/health`.
- Add an ordered initial migration containing users, workspaces, memberships,
  sessions, projects, tasks, constraints, and indexes.
- Run embedded migrations during server startup.
- Add configuration and health-route tests.
- Verify formatting, Clippy, unit tests, and migration compilation.

Commit: `feat(server): add Axum and PostgreSQL foundation`

## 3. Authentication

- Add pure email, password, and name validation.
- Implement Argon2id password hashing in blocking tasks, secure random session
  tokens, SHA-256 token storage, and bearer authentication.
- Implement atomic registration, login, logout, and session restoration.
- Test normalization, token hashing, registration rollback, duplicate accounts,
  invalid credentials, session expiry, and raw-token non-persistence.

Commit: `feat(auth): add persistent server sessions`

## 4. Workspaces and projects

- Implement authenticated workspace list, create, rename, and activate routes.
- Implement project list, create, rename, and archive routes.
- Enforce membership and workspace ownership in every SQL statement.
- Test multi-workspace membership, active workspace changes, project uniqueness,
  and cross-workspace denial.

Commit: `feat(workspace): add workspace and project management`

## 5. Tasks and vault

- Implement task validation, list filters, create, read, update, movement, and
  archive routes.
- Add the filesystem vault with typed UUID paths and atomic Markdown writes.
- Create an empty Markdown document with each task and expose authorized document
  read and write routes.
- Test Inbox semantics, project movement, search, priority/status changes,
  workspace isolation, faithful Markdown round trips, and temporary-directory
  vault behavior.

Commit: `feat(task): add structured tasks and Markdown vault`

## 6. Desktop connection and authentication

- Add the typed fetch client, server URL normalization, local preferences, and
  TanStack Query provider.
- Build connection, registration, and login views with useful validation and
  error states.
- Restore sessions on launch and handle unauthorized responses consistently.
- Test server configuration, auth forms, token persistence, and failure states.

Commit: `feat(desktop): add server connection and authentication`

## 7. Workspace task interface

- Build the three-pane shell, workspace switcher, Inbox/project navigation,
  project and workspace creation/rename actions, task rows, filters, and detail
  metadata controls.
- Add task search, creation, movement, status/priority editing, and archiving.
- Add keyboard shortcuts and semantic focus management.
- Test core user behavior and mutation error recovery.

Commit: `feat(ui): add workspace project and task workflow`

## 8. Markdown experience

- Add CodeMirror Markdown source editing.
- Add safe GitHub-flavored rendering with Edit, Preview, and Split modes.
- Add debounced autosave, explicit save, save-state feedback, and navigation
  protection after failed or pending saves.
- Test safe rendering, source fidelity, save shortcuts, autosave, error recovery,
  and reload persistence.

Commit: `feat(markdown): add editor preview and autosave`

## 9. Visual and accessibility refinement

- Complete the design tokens, light/dark themes, pane hierarchy, dense row
  states, focus/hover/selection behavior, empty states, loading states, long
  title handling, and narrow-window controls.
- Run the browser application against a real server, capture and inspect the
  principal states, and correct visible layout or interaction problems.
- Re-run frontend accessibility-focused behavior tests.

Commit: `feat(ui): refine desktop workspace experience`

## 10. Self-hosting, end-to-end tests, CI, and docs

- Add the multi-stage server image, two-service Compose stack, environment
  examples, persistent data layout, and health checks.
- Add Playwright coverage for the complete persistent workflow and a second-user
  workspace-isolation scenario.
- Add GitHub Actions for Rust, frontend, PostgreSQL integration, and reliable E2E
  checks.
- Write the concise README, architecture guide, development guide, and future
  agent instructions.

Commits:

- `feat(infra): add self-hosted deployment`
- `test(e2e): cover the Kanleaf workflow`
- `ci: add project quality checks`
- `docs: complete contributor guidance`

## 11. Final audit

- Run Rust formatting, Clippy with warnings denied, all Rust tests, TypeScript
  checking, ESLint, Prettier checking, frontend tests, production build, and
  Playwright.
- Inspect the rendered Tauri/browser UI at normal and narrow desktop widths.
- Scan source and configuration for deferred markers, template content,
  hard-coded deployment paths, debug logging, unsafe request-path panics,
  unused dependencies, dead modules, and accidental generated commentary.
- Inspect the complete tree, diff, history, ignore rules, and runtime data paths.
- Correct reasonable findings, commit the audit fixes, and leave the worktree
  clean without pushing a remote branch.

Commit when changes are required: `chore: complete v0.1 readiness review`
